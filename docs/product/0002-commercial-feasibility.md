# 0002 — 商业化可行性分析报告

> 状态：proposal。数字未经测算脚本生成，见 [0070](0070-review.md) 第 5 节。

## （一）市场分析

### 1）目标客户

- **C 端**：独立开发者、自由外包程序员（主力付费人群）
- **小 B**：3–10 人初创研发团队、小型软件外包工作室
- **痛点**：团队人手不足，缺少专职前端、测试、运维。项目从开发到部署全链路重复劳动。单 Agent 来回轮次太多，重构大项目效率极低。通用 Agent 不懂 Web 工程规范，输出大量不符合项目结构的代码

### 2）竞品矩阵

| 产品 | 模式 | 短板 | K9999 优势 |
|---|---|---|---|
| Pi | 单 Agent 串行、通用编码 | 无原生多角色、无任务调度、只能单步调用 | DAG 多 Agent 分工 + PTC 批量调用，垂直 Web 工程范式 |
| CrewAI | 多 Agent 自由对话 | 无任务 DAG，容易无限闲聊，没有本地文件沙箱 | 中心化调度，严格约束输入输出，内置文件与命令沙箱 |
| Copilot | IDE 插件、单轮思考 | 只做代码补全，无法完成项目整体规划与部署 | 全链路闭环：需求 → 架构 → 编码 → 测试 → 部署 |

### 3）市场规模（TAM / SAM / SOM）

- TAM：国内独立开发者加小微研发团队 ≥ 80 万人
- SAM：愿意付费购买本地开发工具人群 ≈ 12 万人
- SOM：首年可触达付费用户 ≈ 1500 人，团队客户 30 家

## （二）技术可行性

1. 底层：Bun + TS 实现 Agent Loop、TUI 交互、会话树，完全脱离 Node 环境，一键编译单二进制，跨 Windows / Mac / Linux 分发
2. 多 Agent：中心化调度器加 DAG 任务图，技术方案成熟，不存在技术卡点
3. 工具层：MCP 协议对接文件读写、Shell、Git、Docker，复用 v1 已验证的沙箱与人工审批能力
4. 核心创新：PTC 批量脚本执行，在 Agent 内核解析简易脚本，一次性执行多步工具调用。纯代码改造，无技术门槛

## （三）盈利模式（三层营收）

### 模式 1：个人版（基础现金流）

- 免费版：基础单 Agent，仅支持前后端编码，BYO 模型密钥（OpenAI / 通义 / 豆包）
- 付费永久许可：**99 元 / 终身**。解锁全部 5 个角色、PTC 批量调用、项目级记忆、本地会话树。二进制直接下载，无服务器依赖

### 模式 2：团队订阅（稳定 recurring 收入）

- 团队版：**19 元 / 席位 / 月**。支持多人共享项目知识库、操作审计日志、会话导出、权限管控、团队工程模板库

### 模式 3：增值付费扩展包（高毛利）

1. 云原生部署模板包（阿里云 / 腾讯云 Web 应用一键编排）：39 元 / 套
2. 自动化 E2E 测试扩展包：49 元
3. 私有化部署授权（小 B 客户）：一次性授权费 2000–5000 元

## （四）成本测算（极低轻资产）

1. 开发成本：单人全职开发，仅人力成本。无服务器开销，客户端纯本地运行，不上云
2. 运营成本：GitHub 开源运营加技术内容引流，几乎零成本
3. 边际成本：二进制分发零成本，每新增一个付费用户，增量成本 ≈ 0

## （五）盈利测算（基准情景）

- 首年个人付费用户：1500 人 × 99 元 ≈ 14.85 万元
- 团队客户：30 家 × 平均 3 席位 × 年订阅 228 元 / 席位 ≈ 20.52 万元
- 扩展包加私有化授权 ≈ 10 万元
- **首年总营收 ≈ 45 万元，纯利润 ≥ 85%，投入产出比极高**

## （六）风险与应对

1. **同质化复刻风险**：把 DAG 调度与 PTC 批量调用做成内核闭源模块，上层工程能力保持开源，形成"开源引流 + 内核闭源变现"模式
2. **LLM 幻觉风险**：内置 Web 工程规则校验器，自动拦截不合理架构、错误 SQL、不安全 Shell 命令
3. **用户增长不足**：依托 GitHub 开源、技术博客、短视频 Demo 演示，主打"小团队 Web 项目交付效率提升 50%"卖点

## （七）可行性结论

市场需求真实，差异化壁垒清晰，技术无卡点，成本极低，盈利模型健康。**立项可行，可以启动开发。**

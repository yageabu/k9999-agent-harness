快速开始 源码 npm i -g k9999
定义

四条属性，都不在 harness 里。

pi-agent-core 提供 agent 循环、sessions、compaction； pi-durable 提供持久化、inbox、task graph、usage。 下面这四样它们故意都不表态 —— 所以它们才是这个项目要做的事。

Evaluatable

可评测

结果由谓词判定，不由模型对自己的评价判定。任务集、转录、离线 replay、预算。

Observable

可观测

终端和浏览器两个界面，读的是同一份已提交状态。渲染词汇表与 sink 接缝。

Bounded

有安全边界

凭据隔离、工具权限门、网络出口可见、审计可回查。四条规则，每条一个测试。

Iterating

持续迭代

上一次会话的结果改变下一次的输入，而记忆的置信度来自实测结果，不来自模型的自信。

为什么换到 pi-durable

ADR-0017。原来打算自建的那一层 —— Storage 接缝、不可变条目、每次转换后完备的操作状态、 resume() —— 已经作为 @earendil-works/pi-durable 发布了。 ADR-0009 的回看条件写着"有已发布的东西提供同一套底层时重新评估"， 而它自己定的检查方法是看已安装的包导出了什么，不是看 checkout 里有什么。

代价是 chord，1.4MB 的应用组合运行时。它的自述动机场景恰好就是这个项目： “an agent worker, a terminal UI, and a remote WebUI”。

一个查询证明的

pi-durable 不依赖 pi-agent-core。它是兄弟，不是层：

$ npm ls @earendil-works/pi-durable
  pi-durable → chord, pi-ai
  (无 pi-agent-core)
安全

凭据曾经是读得到的。

spawn("/bin/bash", ["-c", cmd]) 没有传 env， 于是子进程继承了整个进程环境。模型写一条 printenv DEEPSEEK_API_KEY， key 就进了工具结果 —— 而工具结果是一条已提交的 entry， 会在会话结束前每一轮都重新发给 provider。

探测命令修复前修复后
printenv DEEPSEEK_API_KEY | wc -c36 字节0
env | wc -l49 个10 个
echo $PATH | wc -c可用可用

白名单而不是黑名单。区别不是风格：黑名单命名的是禁止什么，因此它授予了以后有人往宿主机加的任何东西。

同一个洞，在 pi-durable 自带的那把工具里

NodeExecutionEnv 接一个 shellEnv，看起来是放白名单的地方。它不是： 

function getShellEnv(baseEnv, extraEnv, inheritEnv = true) {
  if (!inheritEnv) return { ...extraEnv };
  return { ...process.env, ...baseEnv, ...extraEnv };
}

process.env 铺在 shellEnv 底下，所以它只是覆盖层。 包装成 guardedEnv 的话，调用方主动要求继承也会被拒 —— 这样它自带的工具和以后加的扩展都一起被保护。

GitHub Packages 上同一份构建叫 @yageabu/k9999，因为那个 registry 要求名字带 owner 作用域。 它即使是公开包也要认证，所以 npmjs 仍是指令里的路径。

API key 怎么设
bash / zshexport DEEPSEEK_API_KEY=sk-…
PowerShell$env:DEEPSEEK_API_KEY="sk-…"
cmd.exeset DEEPSEEK_API_KEY=sk-…

export 是 bash 内建命令，PowerShell 和 cmd 会拒绝它。 TUI 是长驻进程，行内前缀到不了它 —— 必须先 export。 缺 key 时报错在提交 prompt 几秒之后才出现，因为模型只在那一刻才被调用。

Windows

在 WSL 下运行。 bash 工具无条件 spawn /bin/bash，原生 Windows 上那是 ENOENT —— 实测 Windows 10 22H2 / Node 22.22.3。读文件和改文件仍然可用，但 agent 永远跑不了任何东西， 也就无法验证自己的改动，而这正是这个 harness 存在的理由。 Git Bash 救不了：它的 /bin 是 MSYS 挂载，Node 不做那个转换。

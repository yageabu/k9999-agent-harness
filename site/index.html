K9999 Agent Harness
为什么 架构 Profile 实测 开始

MIT · TypeScript · Node ≥ 22.19

在 pi-agent-core 之上
组装你自己的 Agent Harness

不是 Pi 的 fork，也不是 Cordis 应用。内核、模型层、provider 覆盖来自上游； profile、prompt 组装、工具注册表、CLI 全部归你所有。 两条命令跑起来，不需要 API key 就能跑完 18 个测试。

$ npm run check ✓ 18 tests · 0 credentials 2 packages · 3 tools

01 / WHY

三个数字，决定架构

启动延迟和安装体积都是在这台机器上实测的，不是估算。决策写成 ADR，每条都标注了代价和重新考虑的触发条件。

10 ms

裸 RUST 二进制

Codex 的原生二进制启动只要 10ms。看起来值得为它换语言。

465 ms

走 NPM 之后

同一个二进制经 npm 的 Node 壳启动要 465ms，比 Pi 的 415ms 还慢。

309 MB

换来的安装体积

Codex 装 309MB，Pi 装 21MB。npm 分发路径把内核优势全部吃掉。

所以 Rust 在这个项目里是叶子，不是核心：只在 OS 级沙箱、进程树与 PTY 控制、CPU 密集任务这三件事上引入 native addon，不引入第二套核心和协议边界。

02 / ARCHITECTURE

一个函数就是全部组装

没有 DI 容器，没有配置语法，没有隐藏接线。createHarness() 是唯一的组合点。

运行时组装路径 
profiles/code/                    packages/core/              packages/cli/

  profile.json ──────┐
   tools: [read,bash,edit]   ┌──▶ createHarness() ──▶ Agent ──▶ renderer
   thinkingLevel: medium     │         │              │       text_delta
  system.md ────────┘         │    ┌────┴─────┐        │       tool 事件
   行为准则 + 8 条输出规则      │    ▼          ▼        │

                                │  edit
                                └── buildSystemPrompt()
                                     1. system.md（作者文本，{{cwd}} 插值）
                                     2. ## Available tools（自动生成）
                                     3. ## Skills（自动生成）
                                     4. Current working directory

PROFILE 是唯一机制

Agent 类型的全部差异收敛到一个目录里的两个文件，可在一份 diff 里 review。没有条件分支 prompt，没有散落在 shell history 里的 flag。

名字 → 实现单点映射

profile 用字符串声明工具。未知名字在加载时报错并列出合法值，而不是静默地少跑几个工具。

层有方向

packages/core 不 import packages/cli。事件的语义归 core，事件长什么样归 CLI。

03 / PROFILES

两种 Agent，两个目录

k9999 -p data 就是全部调用方式。每个 profile 的 prompt 里都带同一套 8 条输出规则。

Profile模型思考等级工具设计意图
code deepseek-flash medium read · bash · edit 最小改动 + 必须给出验证命令和实际输出
data deepseek-v4-pro high read · bash 刻意不给 edit：数据 Agent 用 bash 写脚本到文件，改你仓库是另一个尚未做出的决定

有测试专门卡住"data profile 不得暴露 edit/write"。约束写进测试，才不会在后续重构里悄悄消失。

04 / EVIDENCE

输出规则来自实测，不是直觉

ASD-STE100 是航空文档的受控语言，53 条规则加约 900 词的受控词典。把它当指令注入确实有效，但同一份研究自己的数据说明了更好的做法。

条件 词数 句数 破折号 粗体 标题 列表项
不加指令 24918.932 521935
完整 STE skill 17113.417 24322
8 行提示 1505.82 000

原作者的结论：skill 只在自己的 linter 上赢，五十多条规则稀释了真正起作用的那五条。完整规则还带一个漏洞——STE 豁免代码块和列表项的句长限制，模型于是把所有东西都做成列表项。
结论进 ADR-0007：提取规则，不引用标准，不附带词典。完整的数据和自测方法在 docs/writing-rules.md。

八条规则

规则 1–5 来自 STE。规则 6–8 不是——它们管的是"交付形态"，而任何受控语言都对此一言不发，却贡献了大部分压缩量。

  1. 句长上限指令句 20 词，描述句 25 词。回答前数一遍最长的三句，超了就拆开。
  2. 条件在前，动作在后If the test fails, read the log.
  3. 一词一义整篇不得为同一个概念轮换同义词。把一件事说三遍是最大的长度浪费。
  4. 禁破折号与分号破折号藏起了两个陈述之间的关系。要么点明关系（because / but / for example），要么写成两句。
  5. 删掉不承载事实的词simply · seamlessly · robust · powerful · leverage · in order to。替换：utilize→use，prior to→before。
  6. 固定的交付形态散文。超过三个部分才用标题，且绝不以标题开头，结尾不加总结。
  7. 无开场白、无结束语不复述问题，不总结刚说过的话，不问"还需要更多吗"。
  8. 不编造具体信息来源没有给数字或原因，就保持概括陈述。

05 / START

两条命令，零凭据验证

测试用脚本化 provider 驱动，整条链路——模型请求、工具执行、二次请求、回合结束——都不需要网络。

bash 
# 安装并验证：typecheck + 18 个测试，不需要 API key
$ npm install
$ npm run check
  # tests 18
  # pass 18
  # fail 0

# 列出 profile
$ npm run k9999 -- --list
  code         Code Agent
  data         Data Analysis Agent

# 交互，或单次运行
$ npm run k9999 -- -p data
$ DEEPSEEK_API_KEY=... npm run k9999 -- --print "prompt.ts 的组装顺序是什么？"

# 失败是响亮的，不是静默的
$ npm run k9999 -- --print "hi"
  Provider is not configured: deepseek
  exit 1

06 / STATUS

已经能用的，和还没做的

缺口写在文档里，不藏在路线图里。两条缺口各有对应 ADR 记录理由。

已交付

Profile 加载与校验 · prompt 组装（顺序有测试锁定）· 工具注册表（read / bash / edit）· 技能解析与渲染 · provider 注册 · CLI（print 模式与 REPL）· 事件渲染 · 18 个测试

DEFERRED

MCP —— ADR-0008 明确推迟。当前路径是把 MCP 工具写成普通 tool 模块注册进 TOOL_FACTORIES，不为它先建沙箱和发现层。

半成品

技能调用 —— 声明的技能会解析、校验、渲染进系统提示，但读取靠 Agent 自己调 read，尚无技能调用工具。

有意为之

没有扩展生态 —— 没有可借用的 ExtensionAPI。Pi 扩展不等于 K9999 扩展，这是自己拥有上层的代价，写在 ADR-0001。
